## Project Overview

This repository documents a structured audit of my weekly workflow as a BCA student and AI Engineering intern, carried out to identify which recurring tasks are good candidates for AI delegation, AI collaboration, or full automation, and which ones should stay firmly in human hands.

The audit was built on top of Anthropic's AI Fluency framework (the 4D model: Delegation, Description, Discernment, Diligence) and applied directly to my own week — coding, documentation, learning, and admin work — rather than to a hypothetical scenario. The goal was to end up with a workflow I could actually adopt, not just a report to submit.

## Assignment Objective

1. Audit my current weekly workflow and classify each recurring task by how much AI involvement it genuinely needs.
2. Configure a dedicated Claude project for ongoing AI-assisted engineering work.
3. Complete Anthropic's AI Fluency course and apply its concepts to real tasks.
4. Set up a clean, professional GitHub repository to host the audit.
5. Select three target tasks and redesign their workflow around responsible AI use.

## Learning Goals

- Build a working vocabulary for talking about AI collaboration (the 4D framework) instead of vague terms like "using AI."
- Get comfortable deciding *when not* to use AI, which turned out to be the harder skill.
- Practice verifying AI output instead of trusting it by default.
- Turn a one-off audit into a repeatable weekly habit.
- Produce documentation that is actually useful to re-read later, not just written to be submitted.

## Key Learnings

- AI classification isn't binary. Most of my tasks landed in "Collaborate with AI," not "Fully Automate" — the honest answer for most engineering work right now.
- Description quality determines output quality more than any other single factor. Vague prompts produced generic code; specific ones produced usable code.
- Verification is a separate skill from delegation. Knowing *how* to check AI output (reading a diff, running tests, tracing logic) mattered more than knowing how to prompt.
- The tasks I was most tempted to fully automate (documentation, boilerplate) were also the ones where unreviewed AI output was most likely to introduce quiet errors.

## Future Improvements
